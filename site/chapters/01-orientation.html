Chapter 01 · Foundations

A QR factory for Verus requests

Nine tabs, one pipeline: validate a form, build a VDXF request, sign it through the daemon, encode it as a deeplink, render a QR.

FIGURE 1.1 · The shape of the codebase.

What the app is

A small Express server with a form per request type. Each form posts JSON to an endpoint; the endpoint builds a VDXF request with verus-typescript-primitives, signs it through a Verus daemon over RPC using verusid-ts-client, encodes it as a wallet deeplink, renders a QR code, and returns both as JSON for the page to display.

It is the reference implementation of "how do I actually produce one of these things", which makes it the right second book after the primitives: everything here is application code built on that library.

Run it

yarn install
# config.js: RPC_HOST, RPC_PORT (18843 = testnet), RPC_USER, RPC_PASSWORD,
#            SERVICE_SIGNER_IADDRESS / SERVICE_SIGNER_WIF for the service signer tab
yarn ui          # Express + EJS UI on :3000
yarn main        # CLI mode: identity update only, prints a terminal QR

RPC_PORT === 18843 is the switch that decides testnet everywhere in the app — not a separate flag. That single comparison picks the system id, the identity chain, and the FLAG_IS_TESTNET bit.

How to read this book

Chapter 2 is the shared half that all nine tabs use. Every later chapter is then short: the tab's form fields, the details object it builds, the flags it sets, and the one thing that makes that request type different. Chapter 12 puts the whole thing back together.
